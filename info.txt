================================================================================
                    MODULE 1: BATTERY HEALTH & DEGRADATION ANALYSIS
================================================================================

Purpose: Detect long-term battery wear before devices reach users.

Implementation Files:
- Manager: BatteryHealthManager.java
- Model: BatteryHealth.java
- DAO: BatteryHealthDao.java
- UI: HealthFragment.java

FEATURES:

1.1 Real Battery Health Estimation
    - Goes beyond Android's basic percentage
    - Uses charge counter data (BATTERY_PROPERTY_CHARGE_COUNTER)
    - Calculates actual mAh capacity vs design capacity
    - Formula: healthPct = (currentCapacity / designCapacity) * 100

1.2 Capacity Fade Tracking
    - Monitors design capacity vs actual capacity over time
    - Tracks capacity fade percentage: capacityFade = 100 - healthPct
    - Records estimatedCapacityMah from discharge cycles
    - Uses 72-hour discharge window for capacity estimation

1.3 Cycle Count Estimation
    - Calculates charge cycle equivalents from total charge/discharge
    - Formula: cycleEquivalents = totalChargeAccumulated / designCapacity
    - Tracks both partial and full cycles
    - 7-day rolling window for cycle calculation

1.4 Battery Aging Model
    - Degradation rate per month (fadePerMonth)
    - Degradation per 100 cycles (fadePer100Cycles)
    - Degradation trend classification: "stable", "gradual", "accelerating"
    - Predicted End-of-Life (EOL) in months when health drops below 80%

1.5 Early Detection of Abnormal Degradation
    - hasAbnormalWear: Flags when health < 80% or degradation > 5%/month
    - hasAbnormalAging: Flags when fade > 3% per 100 cycles
    - hasSwellingRisk: High temp during non-charging indicates swelling
    - hasCalibrationIssue: >10% mismatch between reported and actual level

1.6 Supplier/Batch Quality Tracking
    - Stores batteryModel, manufacturer, batchId
    - Calculates supplierAverageHealth across all devices
    - Calculates batchAverageHealth for batch comparison
    - Enables OEM to catch bad battery batches

SCORING SYSTEM:
- capacityScore: Based on health percentage (0-100)
- resistanceScore: Based on internal resistance (60-100)
- cycleScore: Based on cycle count vs 800 cycle baseline (0-100)
- overallScore: (capacityScore * 0.6) + (cycleScore * 0.3) + (resistanceScore * 0.1)

OEM VALUE:
- Catch bad battery batches early
- Validate supplier quality
- Predict warranty risks
- Data-driven supplier negotiations

FEATURES:

3.1 Real-Time Battery Temperature Tracking
    - Continuous monitoring via BatteryManager
    - Temperature in tenths of degrees (converted to Celsius)

3.2 Temperature Spike Detection
    - WARNING threshold: 42°C

                MODULE 4: BATTERY DRAIN ROOT-CAUSE ANALYSIS (AI-DRIVEN)
================================================================================

Purpose: Identify why battery drains faster than expected.

Implementation Files:
- Managers: DrainAnalyzer.java, AppDrainRanker.java, AppUsageCollector.java
- Models: DrainEvent.java, AppBatteryUsage.java, AppDrainRank.java
- DAOs: DrainEventDao.java, AppBatteryUsageDao.java, AppDrainRankDao.java
- UI: DrainFragment.java

FEATURES:

4.1 App-Wise Battery Drain Ranking
    - Collects per-app usage via UsageStatsManager
    - Computes drainScore per app:
      drainScore = drain + (screenTime * 1.0) + (fgTime * 0.7) + (bgTime * 0.4) + (wakelock * 0.3)
    - Ranks top 5 apps by contribution
    - Calculates contributionPct for each app

4.2 System App vs User App Comparison
    - Separates system apps from user-installed
    - Tracks systemPct vs userPct attribution
    - Identifies misbehaving pre-installed apps

4.3 Background Wake-Lock Detection
    - Tracks partialWakelockTime per app
    - Records wakelockCount
    - Calculates wakelock contribution to drain
    - Flags excessive background activity

4.4 Network Drain Analysis
    - networkType: "mobile", "wifi", "none"
    - networkDrainEstimate: 40% of drain for mobile, 20% for wifi
    - Correlates network state with drain rate

4.5 Screen-On vs Screen-Off Drain Analysis
    - Separate tracking for screenOn events
    - Calculates screenOnTime per drain event
    - displayDrainEstimate: (brightness/255) * drainRate
    - cpuDrainEstimate: (cpuLoad/100) * drainRate

DRAIN EVENT CLASSIFICATION:
- drainType: "heavy", "normal", "idle", "standby"
- drainCategory: "display", "system", "idle"
- expectedDrain vs actual (anomaly detection)
- anomalyScore: (actual - expected) / expected

DRAIN METRICS:
- startLevel, endLevel, drainAmount
- drainRatePerHour
- primaryCause (top app/process)
- recommendations for excessive drain

OEM VALUE:
- Optimize system apps
- Detect misbehaving pre-installed apps
- Improve standby time benchmarks
- Data-driven app optimization

                MODULE 5: IDLE DRAIN & STANDBY POWER LEAKAGE DETECTION

Purpose: Ensure minimal battery loss when phone is idle.

Implementation Files:
- Manager: IdleDrainAnalyzer.java
- Model: IdleDrainSession.java
- DAO: IdleDrainSessionDao.java
- UI: IdleFragment.java

FEATURES:

5.1 Deep Sleep Success Rate
    - Tracks deepSleepPercentage: time in doze / total idle time
    - deepSleepSuccessRate: ratio of successful deep sleep
    - Monitors dozeEntryTime and dozeExitTime

5.2 Idle Drain Per Hour
    - drainPerHour: drainAmount / durationHours
    - Benchmarking:
      * Excellent: <0.3%/hr
      * Good: 0.3-0.5%/hr
      * Fair: 0.5-1.0%/hr
      * Poor: 1.0-2.0%/hr
      * Failing: >2.0%/hr

5.3 Doze Mode Effectiveness Validation
    - dozeEffectiveness: 100 - (drainPerHour * 200)
    - dozeEffectivenessScore (0-100)
    - Tracks dozeActive state
    - sessionType: "deep_doze" or "idle"

5.4 Background Service Leakage Detection
    - hasLeakage: drainPerHour > 1.0 or wakeups > 3
    - leakageSources: "alarms/network"
    - leakageClass: "NORMAL", "WARNING", "LEAK"
    - Classification based on:
      * Drain rate
      * Deep sleep rate
      * Wakeup count

5.5 Wake-Up Tracking
    - alarmWakeups: Count of alarm-triggered wakes
    - networkWakeups: Count of network-triggered wakes
    - Total wakeup impact on idle drain

IDLE SESSION FIELDS:
- startTime, endTime, startLevel, endLevel
- drainAmount, drainPerHour
- expectedDrain (0.5%/hr baseline)
- drainDelta: actual - expected
- recommendations

OEM VALUE:
- Meet standby benchmarks
- Catch firmware bugs
- Improve real-world battery life claims
- Validate doze implementation

Purpose: Ensure battery percentage shown is accurate.

Implementation Files:
- Manager: CalibrationManager.java
- Model: CalibrationData.java
- DAO: MiscDao.java
- UI: CalibrationFragment.java

FEATURES:

9.1 Battery Percentage Drift Detection
    - Compares reportedLevel vs estimatedActualLevel
    - levelDrift = estimatedActualLevel - reportedLevel
    - driftDirection: "under_reporting", "over_reporting", "stable"
    - Tracks avgDrift and maxDrift over time

9.2 Calibration Recommendation Engine
    - needsCalibration: |drift| > 8% or hasSuddenDrops
    - calibrationRecommendation: "Discharge to 5% then charge to 100%"
    - calibrationSchedule: "Run calibration this week" or "Recheck monthly"
    - daysSinceCalibration tracking

9.3 Sudden Drop Issue Detection
    - Detects: >= 5% drop in <= 15 minutes
    - suddenDropCount counter
    - avgDropSize, worstDrop metrics
    - hasSuddenDrops flag

9.4 AI-Based SOC (State of Charge) Correction
    - correctedSoc: reportedLevel + levelDrift
    - correctionConfidence (0-100%)
    - Based on: recency, drift penalty, drop penalty, sample count, trend
    - Formula: 30 + sampleScore + trendBonus - driftPenalty - dropPenalty

CALIBRATION METRICS:
- reportedLevel, estimatedActualLevel
- levelDrift, driftExceeded (|drift| > 8)
- socMismatch (|drift| > 5)
- socAccuracy: 100 - |drift|
- calibrationQuality: 100 - (|drift| * 2) - (drops * 5)

CALIBRATION TRACKING:
- lastFullCharge, lastLowBattery, lastDeepDischarge
- fullChargeCount, deepDischargeCount
- lastCalibration timestamp
- isCalibrated: quality >= 70 and no sudden drops

HEALTH IMPACT:
- healthImpactScore: |drift| * 0.5 + drops * 2
- Affects overall device reliability score

OEM VALUE:
- Prevent user trust issues
- Improve UX accuracy
- Reduce service center complaints
- Identify fuel gauge IC issues

================================================================================
                         ANDROID SYSTEM APIs USED
================================================================================

1. BatteryManager API
   ─────────────────────────────────────────────────────────────────────────────
   Location: android.os.BatteryManager
   Used in: BatteryDataCollector.java, BatteryReceiver.java, BatteryMonitorService.java
   
   Data Retrieved:
   - EXTRA_LEVEL: Battery percentage (0-100)
   - EXTRA_SCALE: Maximum battery level
   - EXTRA_STATUS: Charging/Discharging/Full/Not charging
   - EXTRA_HEALTH: Good/Overheat/Dead/Over voltage/Unspecified failure
   - EXTRA_PLUGGED: AC/USB/Wireless charging source
   - EXTRA_VOLTAGE: Battery voltage in millivolts
   - EXTRA_TEMPERATURE: Battery temperature in tenths of °C
   - EXTRA_TECHNOLOGY: Battery chemistry (Li-ion, etc.)
   - BATTERY_PROPERTY_CHARGE_COUNTER: Remaining capacity in microampere-hours
   - BATTERY_PROPERTY_CURRENT_NOW: Instantaneous current in microamperes
   - BATTERY_PROPERTY_CURRENT_AVERAGE: Average current in microamperes
   - BATTERY_PROPERTY_CAPACITY: Remaining capacity percentage
   - BATTERY_PROPERTY_ENERGY_COUNTER: Remaining energy in nanowatt-hours

2. UsageStatsManager API
   ─────────────────────────────────────────────────────────────────────────────
   Location: android.app.usage.UsageStatsManager
   Used in: AppUsageCollector.java
   Permission Required: PACKAGE_USAGE_STATS (special permission)
   
   Data Retrieved:
   - Per-app foreground time
   - Per-app total time in foreground
   - Usage statistics intervals (daily/weekly/monthly)

3. PowerManager API
   ─────────────────────────────────────────────────────────────────────────────
   Location: android.os.PowerManager
   Used in: BatteryMonitorService.java, BatteryDataCollector.java
   
   Features Used:
   - PARTIAL_WAKE_LOCK: Keep CPU running for background monitoring
   - isDeviceIdleMode(): Check if device is in Doze mode
   - isInteractive(): Check if screen is on
   - isPowerSaveMode(): Check if battery saver is active

4. ActivityManager API
   ─────────────────────────────────────────────────────────────────────────────
   Location: android.app.ActivityManager
   Used in: BatteryDataCollector.java
   
   Data Retrieved:
   - Running processes
   - Memory info
   - Foreground app detection

5. ConnectivityManager API
   ─────────────────────────────────────────────────────────────────────────────
   Location: android.net.ConnectivityManager
   Used in: BatteryDataCollector.java
   
   Data Retrieved:
   - Network type (WiFi/Mobile/None)
   - Network state

6. Intent Broadcasts (System Events)
   ─────────────────────────────────────────────────────────────────────────────
   Used in: BatteryReceiver.java, BatteryMonitorService.java
   
   Broadcasts Monitored:
   - ACTION_BATTERY_CHANGED: Any battery state change
   - ACTION_POWER_CONNECTED: Charger plugged in
   - ACTION_POWER_DISCONNECTED: Charger unplugged
   - ACTION_BATTERY_LOW: Battery below 15%
   - ACTION_BATTERY_OKAY: Battery above 15%
   - ACTION_BOOT_COMPLETED: Device boot (to restart service)

                         EXTERNAL SERVICES & APIs

1. APPWRITE BACKEND (Cloud Functions)
   ─────────────────────────────────────────────────────────────────────────────
   Purpose: Secure proxy for AI API calls (OpenAI)
   Type: Serverless Functions (NOT database storage)
   
   Configuration Files:
   - AppwriteClientProvider.java: Client initialization
   - AppwriteFunctionCaller.java: Function execution
   - appwrite/functions/proxy/index.js: Serverless function code
   
   BuildConfig Variables Required:
   - APPWRITE_ENDPOINT: e.g., "https://sgp.cloud.appwrite.io/v1"
   - APPWRITE_PROJECT_ID: e.g., "696459cc001abc691815"
   
   Function Details (proxy):
   - Runtime: Node.js 18
   - Authentication: Requires X-Appwrite-User-ID header
   - Rate Limit: 30 requests per minute per user
   - Payload: JSON with "prompt" field (max 4000 chars)
   
   Security Features:
   - Project ID validation
   - User authentication required
   - API keys stored server-side only
   - No secrets exposed to client

   ─────────────────────────────────────────────────────────────────────────────
   Purpose: AI-powered battery analysis insights
   Endpoint: https://api.openai.com/v1/chat/completions
   Access: Through Appwrite function proxy ONLY (keys never on device)
   Model: gpt-4o-mini
   Max Tokens: 128
   
   Usage in HexNil:
   - AI analysis explanations
   - Recommendation generation
   - Issue classification assistance

   - Required for: Continuous battery monitoring

   - Required for: Android 14+ foreground service type
   - Type: Normal permission

   - Required for: Auto-start monitoring on device boot
   - Type: Normal permission

   - Required for: Per-app battery usage data
   - Type: Special permission (requires user grant in Settings)
   - Grant via: Settings > Apps > Special access > Usage access

   - Required for: Detailed battery statistics
   - Type: Signature permission (OEM builds only)
   - Alternative: Limited data via BatteryManager

6. INTERNET
   - Required for: Appwrite function calls
   - Type: Normal permission

7. WAKE_LOCK
   - Required for: Keep CPU running during monitoring
   - Type: Normal permission
