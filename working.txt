================================================================================

HexNil is an OEM-grade battery diagnostics application that provides:
- Continuous real-time battery monitoring
- Per-app battery usage tracking
- Thermal monitoring and alerts
- Charging session analysis
- AI-powered anomaly detection
- Battery health tracking over time
- Detailed compliance and safety reports

Package Name: com.example.hexnil
Database Version: 19
Target SDK: 36 (Android 15)

6. DATA COLLECTION - WHAT IT COLLECTS
================================================================================

A) BATTERY SNAPSHOTS (Every 30-300 seconds, adaptive)
-----------------------------------------------------
Collected at these intervals:
- Normal discharge: 60 seconds
- Charging: 30 seconds
- Fast charging: 20 seconds
- Low battery (<20%): 30 seconds
- Critical battery (<10%): 15 seconds
- High temperature (>40°C): 15 seconds
- Screen off: 2 minutes
- Device idle/doze: 5 minutes

Each snapshot contains:
- Battery level (0-100%)
- Battery status (charging, discharging, full)
- Battery health (good, overheat, dead, etc.)
- Voltage (millivolts)
- Temperature (in tenths of °C, e.g., 285 = 28.5°C)
- Current flow (microamperes)
- Charge counter (microampere-hours)
- Energy counter (nanowatt-hours)
- Screen state (on/off)
- Screen brightness (0-255)
- WiFi/Mobile/Bluetooth/GPS state
- Signal strength (dBm)
- Charging type (USB, AC, Wireless)
- Fast charging status
- CPU usage (%)
- Memory usage (%)
- Doze mode state
- Top foreground app
- Number of running apps
- Validation/quality score

B) APP BATTERY USAGE (Every 5 minutes)
-------------------------------------
For EACH installed app, collects:
- Package name (e.g., com.instagram.android)
- App name (e.g., Instagram)
- Is system app (true/false)
- Foreground time (milliseconds)
- Background time (milliseconds)
- Battery percentage used
- Drain rate per hour (%/hr)
- CPU time consumed (ms)
- Network bytes used
- Wakelock count and duration
- Alarm wake count
- Network wake count
- GPS request count
- Background wakes count
- Push notifications count
- Efficiency rating (efficient/normal/inefficient/problematic)
- Period start and end timestamps

C) CHARGING SESSIONS
-------------------
When you plug in charger, records:
- Start time and end time
- Start level and end level
- Amount charged
- Charging type (USB/AC/Wireless)
- Fast charging status
- Max/Min/Avg voltage
- Max/Min/Avg current
- Temperature curve (start, max, end, avg)
- Charging duration
- Charging speed
- Energy delivered (mAh)
- Charging efficiency (%)
- Power (watts)
- CC phase and CV phase data
- Interruption count and timestamps
- Safety score
- Charger fingerprint

D) DRAIN EVENTS
--------------
When discharging, records:
- Drain start and end time
- Amount drained (%)
- Drain rate per hour
- Context (screen on/off, apps used)
- Was idle or active

E) THERMAL EVENTS
----------------
When temperature exceeds thresholds:
- Event type (warning/critical)
- Max temperature reached
- Duration of high temperature
- Trigger activity (what caused it)
- Throttling occurred (true/false)

F) BATTERY HEALTH RECORDS
------------------------
Periodically tracks:
- Health percentage
- Cycle count estimate
- Degradation rate
- Capacity comparison (design vs actual)

G) ANOMALY RECORDS (AI-detected issues)
--------------------------------------
When AI detects problems:
- Anomaly type (app_drain, thermal, battery_health, charging, usage_pattern, idle_drain)
- Severity (critical, high, medium, low, info)
- Confidence score (0-100%)
- Source app (if app-related)
- Title and detailed description
- Expected vs actual values
- Deviation percentage
- Metric name and unit
- Recommendations
- Root cause analysis
- Impact description
- Time period analyzed

9. MONITORING SERVICE DETAILS
================================================================================

SERVICE NAME: BatteryMonitorService
TYPE: Foreground Service (runs continuously)

WHEN IT STARTS:
1. When app is opened (MainActivity.onCreate)
2. When device boots (BootReceiver)
3. When app starts (HexNilApplication.onCreate)

HOW IT WORKS:
1. Registers for battery broadcast events
2. Captures snapshots at adaptive intervals
3. Runs analysis managers on each snapshot
4. Collects app usage every 5 minutes
5. Runs AI analysis every 30 minutes

BROADCAST EVENTS MONITORED:
- ACTION_BATTERY_CHANGED - Battery state changes
- ACTION_POWER_CONNECTED - Charger plugged in
- ACTION_POWER_DISCONNECTED - Charger unplugged
- ACTION_BATTERY_LOW - Battery below 15%
- ACTION_BATTERY_OKAY - Battery recovered
- ACTION_SCREEN_ON - Screen turned on
- ACTION_SCREEN_OFF - Screen turned off
- ACTION_DEVICE_IDLE_MODE_CHANGED - Doze mode changes

ADAPTIVE SAMPLING INTERVALS:
- Normal discharge: 60 seconds
- Charging: 30 seconds  
- Fast charging: 20 seconds
- Low battery (<20%): 30 seconds
- Critical (<10%): 15 seconds
- High temp (>40°C): 15 seconds
- Screen off: 2 minutes
- Idle/Doze: 5 minutes

MANAGERS INITIALIZED:
1. BatteryDataCollector - Collects snapshots
2. BatteryHealthManager - Tracks health over time
3. ChargingAnalyzer - Analyzes charging sessions
4. ThermalMonitor - Monitors temperature
5. DrainAnalyzer - Analyzes drain patterns
6. IdleDrainAnalyzer - Tracks idle drain
7. SafetyMonitor - Checks safety thresholds
8. CalibrationManager - Calibrates readings
9. ProtectionManager - Protects battery
10. AppUsageCollector - Collects per-app usage
11. HexNilAI - AI analysis engine

CHECK IF SERVICE IS RUNNING:
    adb shell dumpsys activity services com.example.hexnil

Look for: isForeground=true, startRequested=true

10. AI ANALYSIS & ANOMALY DETECTION
================================================================================

AI ANALYSIS RUNS:
- Every 30 minutes automatically
- 5 minutes after app start (initial analysis)
- Can be triggered manually from app

ANOMALY DETECTION THRESHOLDS:
----------------------------
APP DRAIN ANOMALIES:
- High: App drains > 15%/hour
- Critical: App drains > 25%/hour

THERMAL ANOMALIES:
- Warning: Temperature > 40°C
- Critical: Temperature > 45°C

BATTERY HEALTH ANOMALIES:
- Warning: Health < 85%
- Critical: Health < 75%
- High degradation: > 0.5%/month loss

CHARGING ANOMALIES:
- Low efficiency: < 75%
- High temperature during charge
- Excessive interruptions

IDLE DRAIN ANOMALIES:
- High: > 2%/hour while idle
- Critical: > 5%/hour while idle

USAGE PATTERN ANOMALIES:
- Excessive wakelocks: > 50 count
- High background time: > 30 minutes

WHEN ANOMALY IS DETECTED:
1. Creates AnomalyRecord with full details
2. Stores in anomaly_records table
3. Logs to Android logcat
4. Includes: type, severity, expected vs actual, recommendations

VIEW DETECTED ANOMALIES VIA ADB:
    adb logcat | findstr "Anomaly"

12. TROUBLESHOOTING
================================================================================

PROBLEM: App crashes on start
SOLUTION: 
1. Clear app data: adb shell pm clear com.example.hexnil
2. Reinstall: adb install -r app-debug.apk
3. Check logs: adb logcat | findstr "hexnil\|Exception\|Error"

PROBLEM: No data being collected
SOLUTION:
1. Check service running: adb shell dumpsys activity services com.example.hexnil
2. Check permissions granted
3. Grant usage access permission manually in Settings

PROBLEM: App usage not showing
SOLUTION:
1. Go to Settings → Apps → Special app access → Usage access
2. Find HexNil and enable
3. Restart app

PROBLEM: Database migration error
SOLUTION:
1. Clear app data: adb shell pm clear com.example.hexnil
2. This resets database to latest version

PROBLEM: Service stops after some time
SOLUTION:
1. Disable battery optimization for HexNil
2. Lock app in recent apps (if device supports)
3. Check: Settings → Apps → HexNil → Battery → Unrestricted

PROBLEM: High battery usage by HexNil itself
SOLUTION:
1. This is expected for continuous monitoring
2. Service uses ~1-3% per hour
3. Can adjust sampling intervals in code

PROBLEM: Device disconnected from ADB
SOLUTION:
1. Check USB cable connection
2. Toggle USB debugging off/on
3. Run: adb kill-server && adb start-server
4. Accept USB debugging prompt on device
